# Signal Engine Configuration Guide

**Status:** Production Ready  
**Version:** 1.0  
**GAP:** GAP-010 (Signal Generation Framework)

## Overview

The SignalEngine provides centralized signal processing, prioritization, and risk validation for trading signals generated by multiple strategies. This guide covers configuration, usage patterns, and best practices.

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                   Strategy Framework                        │

│         │                 │                 │              │

└────────────────────────┬────────────────────────────────────┘

                         ▼
┌─────────────────────────────────────────────────────────────┐
│                    SignalEngine                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ 1. Collect signals from all strategies             │  │
│  │ 2. Filter by confidence threshold                  │  │

```

## Configuration

### Basic Configuration

```typescript
import { SignalEngine } from './trading/SignalEngine';
import { RiskManager } from './trading/riskManager';

const riskManager = new RiskManager({
  maxExposurePerMarket: 1000,
  maxOpenOrders: 10,
  maxDrawdown: 0.2,
});

const signalEngine = new SignalEngine(
  {
    enabled: true,
    maxSignalsPerToken: 3,
    minConfidence: 0.5,
    conflictResolution: 'highest-confidence',
    maxHistorySize: 1000,
  },
  riskManager
);
```

### Configuration Parameters

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `enabled` | boolean | `true` | Enable/disable signal processing |
| `maxSignalsPerToken` | number | `3` | Maximum concurrent signals per token |
| `minConfidence` | number | `0.5` | Minimum confidence threshold (0-1) |
| `conflictResolution` | string | `'highest-confidence'` | Strategy for resolving conflicts |
| `maxHistorySize` | number | `1000` | Maximum signal history to retain |

### Conflict Resolution Strategies

#### 1. Highest Confidence (Recommended)

Selects the signal with the highest confidence score.

```typescript
conflictResolution: 'highest-confidence'
```

**Example:**
```
Input:
  - Strategy A: BUY @ $0.50 (confidence: 0.7)
  - Strategy B: BUY @ $0.52 (confidence: 0.9)
  - Strategy C: BUY @ $0.51 (confidence: 0.8)

Output:
  - Strategy B: BUY @ $0.52 (confidence: 0.9)
```

**Use Case:** When you trust strategies with higher confidence scores to make better decisions.

#### 2. First Wins (FIFO)

Selects the first signal received (FIFO processing).

```typescript
conflictResolution: 'first-wins'
```

**Example:**
```
Input (in order):
  1. Strategy A: BUY @ $0.50 (confidence: 0.7)
  2. Strategy B: BUY @ $0.52 (confidence: 0.9)

Output:
  - Strategy A: BUY @ $0.50 (confidence: 0.7)
```

**Use Case:** When all strategies are equally trusted, or when you want to prioritize fast strategies.

#### 3. Aggregate

Combines multiple signals into a single aggregated signal.

```typescript
conflictResolution: 'aggregate'
```

**Example:**
```
Input:
  - Strategy A: BUY @ $0.50, size 10 (confidence: 0.7)
  - Strategy B: BUY @ $0.60, size 15 (confidence: 0.8)

Output:
  - Aggregated: BUY @ $0.55, size 25 (confidence: 0.75)
  
Calculation:
  - Price: (0.50 + 0.60) / 2 = $0.55
  - Size: 10 + 15 = 25
  - Confidence: (0.7 + 0.8) / 2 = 0.75
```

**Special Cases:**
- **Opposing signals** (BUY vs SELL with equal count): Signals cancel out → No action
- **Hold signals dominate**: No action taken
- **Majority action**: If 2 BUY and 1 SELL → Aggregated BUY signal

**Use Case:** When you want to combine signals from multiple strategies for stronger conviction.

## Usage Examples

### Basic Usage

```typescript
// 1. Get signals from strategy orchestrator
const evaluationResults = await orchestrator.evaluateAll(marketContext);

// 2. Convert to Signal format
const signals = evaluationResults
  .filter(r => !r.error && r.decision.action !== 'hold')
  .map(r => ({
    decision: r.decision,
    strategyId: r.strategyId,
    strategyName: r.strategyName,
    tokenId: marketContext.tokenId,
    timestamp: r.timestamp,
    qualityScore: r.decision.confidence,
  }));

// 3. Process signals
const signalResults = await signalEngine.processSignals(
  signals,
  currentOrders,
  currentPositions
);

// 4. Execute approved signals
for (const result of signalResults) {
  if (result.approved) {
    const orderId = await executeOrder(result.signal.decision);
    signalEngine.markExecuted(result.signal, orderId);
  } else {
    logger.warn('Signal rejected', {
      reason: result.reason,
      strategyId: result.signal.strategyId,
    });
  }
}
```

### Monitoring Performance

```typescript
// Get performance metrics
const metrics = signalEngine.getMetrics();

console.log({
  total: metrics.total,
  approved: metrics.approved,
  rejected: metrics.rejected,
  approvalRate: `${(metrics.approvalRate * 100).toFixed(1)}%`,
  activeSignals: metrics.activeSignals,
});

// Per-strategy breakdown
for (const [strategyId, stats] of Object.entries(metrics.byStrategy)) {
  console.log(`${strategyId}: ${stats.approved} approved, ${stats.rejected} rejected`);
}

// Get recent history
const recentSignals = signalEngine.getHistory(50);
console.log('Last 50 signals:', recentSignals);
```

### Event Monitoring

```typescript
// Listen to signal processing events
signalEngine.on('signalProcessed', (result) => {
  logger.info('Signal processed', {
    approved: result.approved,
    strategyId: result.signal.strategyId,
    action: result.signal.decision.action,
  });
});

signalEngine.on('signalExecuted', ({ signal, orderId }) => {
  logger.info('Signal executed', {
    strategyId: signal.strategyId,
    orderId,
  });
});

signalEngine.on('signalFailed', ({ signal, error }) => {
  logger.error('Signal execution failed', {
    strategyId: signal.strategyId,
    error: error.message,
  });
});
```

### Emergency Operations

```typescript
// Clear all active signals (e.g., during system reset)
signalEngine.clearActiveSignals();

// Disable signal processing temporarily
const config = signalEngine.getConfig();
const disabledEngine = new SignalEngine(
  { ...config, enabled: false },
  riskManager
);
```

## Integration Patterns

### Pattern 1: Direct Integration

Process signals immediately after strategy evaluation:

```typescript
async function processMarketUpdate(marketContext: MarketContext) {
  // Evaluate strategies
  const results = await orchestrator.evaluateAll(marketContext);
  
  // Convert and process signals
  const signals = convertToSignals(results);
  const approved = await signalEngine.processSignals(signals);
  
  // Execute
  await executeApprovedSignals(approved);
}
```

### Pattern 2: Queue-Based Processing

Buffer signals for batch processing:

```typescript
const signalQueue: Signal[] = [];

async function queueSignals(results: EvaluationResult[]) {
  const signals = convertToSignals(results);
  signalQueue.push(...signals);
}

async function processBatch() {
  if (signalQueue.length === 0) return;
  
  const batch = signalQueue.splice(0, signalQueue.length);
  const results = await signalEngine.processSignals(batch);
  await executeApprovedSignals(results);
}

// Process batches every 5 seconds
setInterval(processBatch, 5000);
```

### Pattern 3: With Orchestrator Conflict Detection

Leverage both orchestrator and signal engine conflict resolution:

```typescript
async function processWithDualConflictResolution(marketContext: MarketContext) {
  // First level: Orchestrator conflict detection
  const orchestratorResult = await orchestrator.evaluateWithConflictDetection(
    marketContext
  );
  
  if (orchestratorResult.hasConflicts) {
    logger.warn('Orchestrator detected conflicts', orchestratorResult.conflicts);
  }
  
  // Use resolved decision if available, otherwise use all results
  const resultsToProcess = orchestratorResult.resolvedDecision
    ? [orchestratorResult.resolvedDecision]
    : await orchestrator.evaluateAll(marketContext);
  
  // Second level: SignalEngine processing
  const signals = convertToSignals(resultsToProcess);
  const approved = await signalEngine.processSignals(signals);
  
  await executeApprovedSignals(approved);
}
```

## Best Practices

### 1. Confidence Threshold

Set `minConfidence` based on your risk tolerance:

- **Conservative (0.7-0.9)**: Only high-confidence signals pass
- **Moderate (0.5-0.7)**: Balance between filtering and opportunity
- **Aggressive (0.3-0.5)**: More signals but higher false positive risk

### 2. Max Signals Per Token

Limit concurrent signals per token to prevent over-trading:

- **Low volatility markets**: 2-3 signals
- **High volatility markets**: 5-10 signals
- **Scalping strategies**: 1-2 signals (quick entry/exit)

### 3. Conflict Resolution Selection

Choose based on strategy trust and trading style:

- **Single best strategy**: Use `highest-confidence`
- **Equal trust strategies**: Use `first-wins` or `aggregate`
- **Consensus-based**: Use `aggregate` to combine signals

### 4. Performance Monitoring

Monitor these key metrics:

```typescript
const metrics = signalEngine.getMetrics();

// Warning thresholds
if (metrics.approvalRate < 0.5) {
  logger.warn('Low approval rate - check risk limits or strategies');
}

if (metrics.activeSignals > config.maxSignalsPerToken * numTokens) {
  logger.warn('High number of active signals - potential issue');
}
```

### 5. History Management

Configure `maxHistorySize` based on memory constraints:

- **Production**: 1000-5000 signals
- **Development**: 100-500 signals
- **High-frequency**: 10000+ signals (requires monitoring)

## Troubleshooting

### Issue: Low Approval Rate

**Symptoms:** Most signals are rejected

**Possible Causes:**
1. Risk limits too strict
2. Confidence threshold too high
3. Market conditions changed

**Solutions:**
```typescript
// Check rejection reasons
const history = signalEngine.getHistory(100);
const rejections = history.filter(r => !r.approved);
const reasons = rejections.map(r => r.reason);
console.log('Top rejection reasons:', 
  Object.entries(
    reasons.reduce((acc, r) => ({ ...acc, [r]: (acc[r] || 0) + 1 }), {})
  )
);
```

### Issue: No Signals Processed

**Symptoms:** `processSignals()` returns empty array

**Possible Causes:**
1. SignalEngine disabled
2. All signals below confidence threshold
3. Strategies generating `hold` decisions

**Solutions:**
```typescript
// Check configuration
console.log('Enabled:', signalEngine.getConfig().enabled);
console.log('Min confidence:', signalEngine.getConfig().minConfidence);

// Check input signals
console.log('Input signals:', signals.length);
console.log('Signal confidences:', signals.map(s => s.decision.confidence));
```

### Issue: High Active Signals

**Symptoms:** Active signals count keeps growing

**Possible Causes:**
1. Signals not marked as executed
2. Execution failures not handled
3. Max signals per token too high

**Solutions:**
```typescript
// Always mark signals after execution
try {
  const orderId = await executeOrder(signal.decision);
  signalEngine.markExecuted(signal, orderId);
} catch (error) {
  signalEngine.markFailed(signal, error);
}

// Periodic cleanup
setInterval(() => {
  const metrics = signalEngine.getMetrics();
  if (metrics.activeSignals > threshold) {
    signalEngine.clearActiveSignals();
    logger.warn('Cleared stuck active signals');
  }
}, 60000);
```

## Migration from Direct Strategy Execution

If you're migrating from direct strategy execution to SignalEngine:

### Before (Direct Execution)

```typescript
const decision = await strategy.evaluate(marketContext);
if (decision.action !== 'hold') {
  await executeOrder(decision);
}
```

### After (With SignalEngine)

```typescript
const decision = await strategy.evaluate(marketContext);

const signal = {
  decision,
  strategyId: strategy.id,
  strategyName: strategy.name,
  tokenId: marketContext.tokenId,
  timestamp: new Date().toISOString(),
  qualityScore: decision.confidence,
};

const results = await signalEngine.processSignals([signal]);

for (const result of results) {
  if (result.approved) {
    const orderId = await executeOrder(result.signal.decision);
    signalEngine.markExecuted(result.signal, orderId);
  }
}
```
